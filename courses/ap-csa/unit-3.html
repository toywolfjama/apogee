Core ideas

In Units 1 and 2 you used classes other people wrote. In Unit 3 you write your own: you decide what data each object stores (instance variables), how objects are set up (constructors), and what they can do (methods).

Exam weight

The main skill

Turning a description ("each account has an owner and a balance; you can deposit…") into instance variables, a constructor and methods.

3.1Abstraction and program design

Deciding what a class should know and do.

Abstraction means hiding details so you can think about the big picture. A class is an abstraction: someone using BankAccount calls deposit without knowing how the balance is stored. Methods are abstractions too: write a task once, give it a name, and call it wherever it's needed.

Designing a class from a description

  1. Nouns describing what each object knows become instance variables ("an owner", "a balance").
  2. Verbs describing what it does become methods ("deposit", "withdraw").
  3. What must be known when an object is made becomes constructor parameters.

Designers often sketch this as a class diagram: class name, then attributes, then methods.

BankAccount
- owner : String
- balance : double
+ BankAccount(name : String, start : double)
+ getBalance() : double
+ deposit(amount : double) : void
+ withdraw(amount : double) : boolean

(− means private, + means public.)

3.2Impact of program design

Reliability, privacy, ownership and ethics.

Programs affect people. The AP framework expects you to consider:

System reliability

Testing with many inputs, including edge cases, reduces bugs that could harm users.

Privacy

Collecting personal data creates responsibility to protect it and use it only as users expect.

Intellectual property

Code, libraries and media are owned by their creators. Licenses say how they can be used; using someone's work without permission can be illegal.

Legal and ethical effects

Software can have unintended consequences, such as bias in automated decisions or excluding users with disabilities.

3.3Anatomy of a class

Instance variables, constructors, methods.

public class BankAccount
{
    private String owner;
    private double balance;

    public BankAccount(String name, double start)
    {
        owner = name;
        balance = start;
    }

    public double getBalance()
    {
        return balance;
    }

    public void deposit(double amount)
    {
        if (amount > 0)
            balance += amount;
    }

    public boolean withdraw(double amount)
    {
        if (amount > balance)
            return false;
        balance -= amount;
        return true;
    }

    public String toString()
    {
        return owner + ": $" + balance;
    }
}

Encapsulation: private data, public methods

Instance variables are private: code outside the class can't touch them directly (a.balance = 1000000; is a compile error). Outside code must go through public methods, which can check that changes make sense (deposit ignores negative amounts). This is encapsulation, and on the exam, instance variables should always be private.

Common mistakeRe-declaring an instance variable inside the constructor: double balance = start; creates a new local variable and leaves the instance variable at 0.0. Write balance = start;.
Detailed explanationAccess modifiers and what each part may do

private vs public

private members are visible only inside the class's own code, including in other objects of the same class. public members are visible everywhere. Classes and constructors are normally public; helper methods used only inside the class can be private.

Why encapsulate?

If every class could change a balance directly, you'd have no single place to enforce rules like "no negative deposits". Encapsulation also lets you change how data is stored later without breaking the code that uses the class.

Default values

An instance variable that the constructor doesn't set keeps its default: 0, 0.0, false or null. A local variable has no default and must be assigned before use.

3.4Constructors

Setting up a new object.

A constructor runs once, when new creates an object. Its job is to give every instance variable a sensible starting value.

class Counter
{
    private int count;
    private int step;

    public Counter()
    {
        count = 0;
        step = 1;
    }

    public Counter(int start, int step)
    {
        count = start;
        this.step = step;
    }

    public void click() { count += step; }
    public int getCount() { return count; }
}
Counter a = new Counter();          // uses the no-parameter constructor
Counter b = new Counter(10, 5);     // uses the two-parameter constructor
a.click(); b.click(); b.click();
System.out.println(a.getCount() + " " + b.getCount());
1 20
  • A constructor has the same name as the class and no return type (not even void).
  • A class can have several constructors with different parameter lists (overloading).
  • If you write no constructor, Java provides a default one with no parameters that leaves every instance variable at its default value. Once you write any constructor, that default one is no longer provided.
Mutable objects as parametersIf a constructor receives an object that can be changed (like another class's object) and just stores the reference, the outside code still has an alias to it. To be safe, store a copy.

3.5Writing methods

Accessors, mutators, toString and return values.

class Rectangle
{
    private int width;
    private int height;

    public Rectangle(int w, int h)
    {
        width = w;
        height = h;
    }

    public int area()
    {
        return width * height;
    }

    public boolean isSquare()
    {
        return width == height;
    }

    public void scale(int factor)
    {
        width *= factor;
        height *= factor;
    }

    public String toString()
    {
        return width + "x" + height;
    }
}

Return a value

area() computes and returns an int. A non-void method must return a value of its declared type on every path.

Return a boolean

return width == height; returns the comparison directly; no if needed.

void mutator

scale changes the instance variables and returns nothing.

Rectangle r = new Rectangle(2, 3);
System.out.println(r.area() + " " + r.isSquare());
r.scale(2);
System.out.println(r);    // calls toString automatically

A return statement ends the method immediately. Code after a return on the same path never runs (the compiler reports it as unreachable).

Print vs returnIf the method says it returns a value, return it. Printing inside the method instead of returning loses free-response points.
Detailed explanationParameters, local variables and return paths

Parameters are local variables

A method's parameters exist only while the method runs. They're initialized with copies of the arguments.

Every path must return

if (x > 0) return 1; alone doesn't compile in a method that returns int, because when x ≤ 0 nothing is returned. Add an else or a final return.

Calling other methods of the same class

Inside a class, a method can call another instance method by name alone: if (isSquare()) … calls it on the same object.

3.6Passing and returning object references

Copies of values and copies of references.

Java always passes copies. For a primitive, it copies the value. For an object, it copies the reference, so the method gets a second arrow to the same object.

public static void change(int n, Rectangle r)
{
    n = 99;
    r.scale(10);
    r = new Rectangle(1, 1);
}
int x = 5;
Rectangle box = new Rectangle(2, 3);
change(x, box);
System.out.println(x + " " + box);
5 20x30

Changing a primitive parameter

No effect on the caller.

Calling a mutator on an object parameter

The caller sees the change: same object.

Reassigning an object parameter

No effect on the caller's variable.

Returning references

A method that returns an instance variable that refers to a changeable object lets outside code change the object's insides. Accessors should return primitives, Strings (which can't change) or copies.

Detailed explanationObjects of the same class

Private access across objects

Inside a class's methods, you can access the private variables of any object of that class, not just this. That's how methods like equals or isBiggerThan(Rectangle other) compare: return area() > other.width * other.height;

Methods that build new objects

A method can create and return a new object: public Rectangle doubled() { return new Rectangle(width * 2, height * 2); }. The original is unchanged.

3.7Class variables and class methods

static: one shared copy for the whole class.

A static variable belongs to the class, not to any one object. There is exactly one copy, shared by all objects. A static method belongs to the class too and is called with the class name.

class Student
{
    private static int nextId = 1;
    private String name;
    private int id;

    public Student(String name)
    {
        this.name = name;
        id = nextId;
        nextId++;
    }

    public int getId() { return id; }
    public static int getNextId() { return nextId; }
}
Student a = new Student("Ana");
Student b = new Student("Ben");
System.out.println(a.getId() + " " + b.getId() + " " + Student.getNextId());
1 2 3
  • Static methods can use static variables and other static methods.
  • Static methods can't use instance variables or this directly: there's no particular object.
  • Instance methods can use both instance and static variables.

3.8–3.9Scope, access and the this keyword

Where variables exist, and the current object.

A variable's scope is the part of the program where it can be used.

KindDeclaredCan be used
Instance variablein the class, outside methodsin every instance method of the class
Parameterin a method headeronly inside that method
Local variableinside a method or blockfrom its declaration to the end of its block ({ })

If a local variable or parameter has the same name as an instance variable, the local one shadows it: the plain name means the local variable.

class Temp
{
    private int value = 10;

    public void show()
    {
        int value = 3;
        System.out.println(value + " " + this.value);
    }
}
3 10

this

Inside an instance method or constructor, this refers to the object the method was called on. Uses:

  • Telling a shadowed instance variable apart: this.name = name;
  • Passing the current object to another method: other.compareWith(this);
Common mistakeWriting name = name; in a constructor whose parameter is also called name. That assigns the parameter to itself, and the instance variable stays null. Use this.name = name;.

Free response 2: class design

Writing a complete class from a description.

You get a description and example calls, and you write the entire class. Use the example calls to find the constructor parameters and every method header.

PromptA TicketBooth is created with a capacity and a ticket price. buy(n) sells n tickets if that many are left and returns the total cost; otherwise it sells nothing and returns 0.0. ticketsLeft() returns how many can still be sold. 
TicketBooth t = new TicketBooth(100, 12.5);
t.buy(4);          // returns 50.0
t.buy(97);         // returns 0.0 (only 96 left)
t.ticketsLeft();   // returns 96
Worked example: Write the TicketBooth class.
public class TicketBooth
{
    private int capacity;
    private int sold;
    private double price;

    public TicketBooth(int capacity, double price)
    {
        this.capacity = capacity;
        this.price = price;
        sold = 0;
    }

    /** Sells n tickets if enough are left; returns the cost, or 0.0 if not enough */
    public double buy(int n)
    {
        if (sold + n > capacity)
            return 0.0;
        sold += n;
        return n * price;
    }

    public int ticketsLeft()
    {
        return capacity - sold;
    }
}

Checklist graders use

  1. Class header and private instance variables for everything the object must remember (including things not passed in, like sold).
  2. Constructor with the right parameters that initializes every instance variable.
  3. Each method header matches the example calls (name, parameter types, return type).
  4. Each method's logic: checks, updates to the state, and correct return values.
Think about stateAsk: what must each object remember between method calls? Every such value needs an instance variable. Values that are only needed during one call should be local variables.

Common mistakes

Points students lose most often.

  1. Giving a constructor a return type (public void Counter() is a method, not a constructor).
  2. Redeclaring instance variables as locals in the constructor.
  3. name = name; instead of this.name = name;
  4. Making instance variables public.
  5. Using an instance variable inside a static method.
  6. Thinking a method can change a caller's primitive variable or make the caller's reference point elsewhere.
  7. Forgetting an instance variable for something the object must remember between calls.
