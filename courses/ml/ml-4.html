Machine Learning · Unit 4

Learning that generalizes

Underfitting and overfitting, the bias–variance trade-off, regularization, cross-validation and ensembles like random forests and boosting.

4.1Underfitting and overfitting

The goal of machine learning is never to fit the training data; it's to do well on data the model hasn't seen. Two things go wrong:

Underfitting (high bias)

The model is too simple to capture the pattern. Training error and test error are both high. Fix: a more flexible model, better features, train longer.

Overfitting (high variance)

The model is so flexible it learns the noise in the training set. Training error is low, test error is high. Fix: more data, a simpler model, regularization, early stopping.

As model complexity grows, training error keeps falling, but test error falls and then rises again, a U shape. The sweet spot is at the bottom of the test-error curve. That's what the right-hand chart in the lab shows.

The bias–variance trade-off

The expected test error of a model can be split into three parts:

expected error = bias² + variance + irreducible noise

Bias is error from wrong assumptions (fitting a line to a curve). Variance is how much the model would change if trained on a different sample of data (a degree-11 polynomial swings wildly). Noise is randomness no model can predict. Making a model more flexible lowers bias but raises variance.

Diagnose with learning curvesPlot training and validation error as the training set grows. If both are high and close together → high bias: more data won't help, a bigger model will. If there's a big gap that shrinks as data grows → high variance: more data will help.

4.2Regularization

Regularization adds a penalty for large weights to the loss, so the model only uses big weights when they really pay off:

L2 (ridge): loss = MSE + λ Σ wⱼ²      L1 (lasso): loss = MSE + λ Σ |wⱼ|

λ (lambda)

The regularization strength, a hyperparameter. λ = 0: no penalty. λ huge: all weights forced toward 0 (underfits). Tune it on the validation set.

L2 / ridge / weight decay

Shrinks all weights smoothly. Wiggly curves need huge weights, so L2 smooths the fit. In the lab above, slide λ up with degree 11.

L1 / lasso

Pushes many weights to exactly 0, so it also does feature selection: the model ends up using only the useful features.

Bias is not penalized

The intercept b just shifts predictions up or down; shrinking it would bias every prediction.

Other ways to fight overfitting

TechniqueHow it works
More dataThe single best fix for variance. Data augmentation (flipping, cropping, rotating images) creates more from what you have.
Early stoppingWatch the validation loss while training and stop when it starts going up.
Dropout (neural nets)Randomly switch off a fraction of neurons on each training step, so the network can't rely on any single one.
Simpler modelFewer features, lower polynomial degree, shallower tree.

4.3Cross-validation and tuning

One validation split can be lucky or unlucky, especially with small datasets. k-fold cross-validation uses every example for validation exactly once:

  1. Shuffle and split the training data into k equal folds (k = 5 or 10 is common).
  2. For each fold: train on the other k − 1 folds, measure the score on this fold.
  3. Average the k scores. Their spread tells you how stable the estimate is.
Worked example: 5-fold CV scores are 0.82, 0.85, 0.80, 0.84, 0.79. What's the CV estimate, and how many models were trained?
Mean = 4.10/5 = 0.82. Five models were trained, each on 80% of the data.

Hyperparameter search

Grid search

Try every combination from a list: λ ∈ {0.01, 0.1, 1} × depth ∈ {3, 5, 7} = 9 combinations, each scored with cross-validation.

Random search

Sample combinations at random. With the same budget it usually finds better settings than a grid, because only a few hyperparameters really matter.
The test set is still off-limitsCross-validation happens inside the training data. After choosing the hyperparameters, retrain on all the training data and evaluate once on the untouched test set.

4.4Ensembles: many models are better than one

Average the predictions of many different models and their individual errors partly cancel out. Ensembles win most competitions on tabular data.

Bagging

Bootstrap aggregating: train each model on a random sample of the training data drawn with replacement, then average (regression) or vote (classification). Mainly reduces variance.

Random forest

Bagging with decision trees, plus a twist: at each split a tree may only consider a random subset of the features. This makes the trees more different from each other, so averaging helps more. Robust, few hyperparameters, a great default.

Boosting

Train models one after another, each focusing on the mistakes of the ones before. Gradient boosting fits each new tree to the remaining errors (residuals). XGBoost, LightGBM and CatBoost are popular implementations. Mainly reduces bias.

Feature importance

Tree ensembles can report how much each feature reduced impurity across all splits, a rough guide to what the model relies on.
Worked example: Three independent classifiers are each right 70% of the time. Majority vote accuracy?
The vote is right if at least 2 of 3 are right: 3(0.7²)(0.3) + 0.7³ = 0.441 + 0.343 = 0.784. Better than any single model — but only if their errors are independent.

Unit summary

Fit

Underfit: both errors high (bias). Overfit: low train, high test (variance). Test error is U-shaped in complexity.

Regularization

L2: + λΣw² shrinks weights. L1: + λΣ|w| zeroes some (feature selection). Also: more data, augmentation, early stopping, dropout.

Cross-validation

k folds, train k models, average. Grid or random search over hyperparameters. Test set used once at the end.

Ensembles

Bagging/random forests cut variance; boosting cuts bias. Independent errors cancel in a vote.
