What machine learning is

Supervised and unsupervised learning, features and labels, scaling, train/test splits, leakage and your first model: k-nearest neighbours.

1.1What machine learning is

In ordinary programming you write the rules: if the email contains "FREE MONEY", mark it as spam. In machine learning you give the computer lots of examples (emails already marked spam or not) and an algorithm finds the rules itself. The result is a model: a function with adjustable numbers, called parameters, that have been tuned to fit the examples.

traditional: rules + data → answers      machine learning: data + answers → rules
Kind of learningWhat the data looks likeGoalExamples
Supervisedinputs with the correct answer (label)predict the label for new inputsspam filter, house prices, reading handwritten digits
Unsupervisedinputs only, no labelsfind structure: groups, patterns, compressed versionscustomer segments, anomaly detection
Reinforcementan agent acts and receives rewardslearn actions that earn the most reward over timegame-playing AIs, robot control
Self-supervisedraw data where part of it is hidden and predictedlearn general-purpose representationslarge language models predicting the next word

Supervised problems come in two flavours:

Regression

The answer is a number: tomorrow's temperature, a house price, how many minutes a delivery will take.

Classification

The answer is a category: spam or not spam, which of 10 digits, cat / dog / bird. With two categories it's binary classification.
When ML is the right toolUse ML when the rules are too complicated to write by hand (recognizing faces), when they change over time (fraud patterns), or when you need to personalize for millions of people. If a simple rule works, use the simple rule.

1.2Data: examples, features and labels

A dataset is usually a table. Each row is one example (an observation). Each column is a feature (an input variable), except for the label (the thing to predict).

A model sees each example as a feature vector x = (x₁, x₂, …, x_d), a list of d numbers, and predicts ŷ ("y-hat"). The true label is y. Bold letters and subscripts are just bookkeeping for "the list of numbers".

Turning everything into numbers

Categories → one-hot

A category like neighbourhood ∈ {North, South, East} becomes three 0/1 columns: North = (1, 0, 0), South = (0, 1, 0), East = (0, 0, 1). Don't code them as 1, 2, 3 — that would tell the model East is 'three times' North.

Text and images

Images are grids of pixel brightnesses (a 28 × 28 photo is 784 features). Text is split into tokens that are mapped to numbers (unit 6).

Missing values

Drop the rows, fill in the column average (imputation), or add a 'was missing' flag column. Never silently treat missing as 0.

Outliers

One house listed at $99,999,999 by mistake can drag a whole model. Plot your data first.

1.3Feature scaling

Square feet (hundreds to thousands) and bedrooms (1–5) live on very different scales. Many algorithms, including distance-based ones like k-NN and anything trained by gradient descent, behave badly when features have wildly different ranges. Two standard fixes:

Standardize (z-score): z = (x − μ) / σ      Min–max: x′ = (x − min) / (max − min)

Standardizing gives every feature mean 0 and standard deviation 1. Min–max squeezes every feature into [0, 1].

Fit the scaler on training data onlyCompute μ and σ from the training set, then apply those same numbers to the validation and test sets. Computing them on all the data lets information about the test set leak into training.

1.4Training, validation and test sets

A model that memorizes its training data can score 100% on it and still fail on anything new. What we care about is generalization: performance on data the model has never seen. So we split the data before training:

SetTypical shareUsed for
Training60–80%fitting the model's parameters
Validation10–20%choosing between models and tuning hyperparameters (settings like k in k-NN)
Test10–20%one final, honest estimate of real-world performance. Touch it once, at the end.

Hyperparameters

Settings you choose rather than learn: learning rate, number of neighbours k, tree depth, number of layers. You tune them on the validation set.

Data leakage

Any route by which test information sneaks into training: scaling on all data, duplicate rows across splits, or a feature that's secretly the answer (a 'refund issued' column when predicting fraud). Leakage gives great scores that collapse in the real world.

Random vs time split

Shuffle randomly for ordinary data. For time series (stock prices, sales) train on the past and test on the future, or you'll be 'predicting' with information from tomorrow.

Class balance

If 99% of transactions are legit, a model that always says 'legit' is 99% accurate and useless. Check the class proportions; use stratified splits that keep them the same in every set.

1.5Your first model: k-nearest neighbours

The simplest learning algorithm there is: to classify a new point, find the k training examples closest to it and take a majority vote. "Training" is just storing the data.

distance between x and x′ = √((x₁ − x′₁)² + (x₂ − x′₂)² + … + (x_d − x′_d)²)
Worked example: Training points: A at (1, 1) and (2, 1); B at (4, 4) and (5, 3). Classify (2, 2) with k = 1 and with k = 3.
Distances from (2, 2): to (1, 1) = √2 ≈ 1.41, to (2, 1) = 1, to (4, 4) = √8 ≈ 2.83, to (5, 3) = √10 ≈ 3.16. k = 1: nearest is (2, 1), class A. k = 3: (2, 1) A, (1, 1) A, (4, 4) B → 2 votes to 1, class A.

Small k

Follows every training point, including noise. Jagged boundaries. Overfits.

Large k

Averages over many points. Smooth boundaries. If k is too big it underfits, ignoring real structure.

Cost

Predicting means measuring the distance to every training example, which gets slow with millions of rows.

Curse of dimensionality

In hundreds of dimensions almost all points are roughly the same distance apart, so 'nearest' stops meaning much.

1.6The machine learning workflow

  1. Frame the problem. What exactly are you predicting, for whom, and what counts as success? Pick a metric.
  2. Get and explore the data. Plot it. Look for missing values, outliers, imbalance, leakage.
  3. Prepare features. Encode categories, scale numbers, engineer useful new features.
  4. Split into train / validation / test.
  5. Start with a baseline: predict the average, or the most common class. Any real model must beat it.
  6. Train models and tune hyperparameters on the validation set.
  7. Evaluate once on the test set.
  8. Deploy and monitor. The world drifts; retrain when performance slips.
# The same workflow in Python with scikit-learn
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)
scaler = StandardScaler().fit(X_train)        # fit on training data only
model = KNeighborsClassifier(n_neighbors=5)
model.fit(scaler.transform(X_train), y_train)
print(model.score(scaler.transform(X_test), y_test))   # accuracy on unseen data

Unit summary

ML

Learn rules from examples. Supervised (regression: numbers; classification: categories), unsupervised, reinforcement, self-supervised.

Data

Rows = examples, columns = features, plus a label. One-hot encode categories. Handle missing values and outliers.

Scaling and splits

z = (x − μ)/σ, fit on training data only. Train / validation / test; tune on validation; test once. Watch for leakage and imbalance.

k-NN

Vote among the k closest training points. Small k overfits, large k underfits. Start every project with a baseline.
