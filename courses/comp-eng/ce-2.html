Numbers in binary

Binary and hex, two's complement, overflow, bit masks, text encoding and floating point: how a computer turns everything into 0s and 1s.

2.1Binary, decimal and hexadecimal

A computer stores everything as bits: 0 or 1, off or on, low voltage or high voltage. Group bits together and you can count. Every number system works the same way: each digit is worth the base times the digit to its right.

Binary → decimal: add the place values of the 1s

Worked example: Convert 1011 0110₂ to decimal.
Place values of the 1 bits: 128 + 32 + 16 + 4 + 2 = 182.

Decimal → binary: divide by 2, read the remainders upward

Or subtract the biggest power of 2 that fits: 45 − 32 = 13, 13 − 8 = 5, 5 − 4 = 1, 1 − 1 = 0. The powers used (32, 8, 4, 1) are the 1 bits.

Hex is shorthand for binary

One hex digit is exactly 4 bits (a nibble), so you convert by grouping bits in fours from the right. No arithmetic needed.

Worked example: Convert 1101 0111 1010₂ to hex, and 0x3F to binary and decimal.
Groups 1101 | 0111 | 1010 → D 7 A, so 0xD7A. 0x3F = 0011 1111₂ = 3 × 16 + 15 = 63.
Where you'll see hexMemory addresses (0x7FFE…), colors (#FF8800 is red FF, green 88, blue 00), MAC addresses, and error codes. Programmers use it because it's compact but still maps directly onto bits.

2.2How many bits do you need?

n bits can represent 2ⁿ different values. To give N different things their own code you need ⌈log₂ N⌉ bits (round up).

32≈ 4.3 billion0 – 4,294,967,295an IPv4 address

Worked example: How many bits to give each of 200 students a unique ID?
2⁷ = 128 is too few, 2⁸ = 256 is enough, so 8 bits.

Units

8 bits = 1 byte. Storage makers use powers of 10 (1 KB = 1000 bytes, 1 GB = 10⁹ bytes). Operating systems often use powers of 2: 1 KiB = 1024 bytes, 1 MiB = 1024² bytes, 1 GiB = 1024³ bytes. That's why a "500 GB" drive shows up as about 465 GiB.

Bits vs bytes

Network speeds are in bits per second (Mb/s, lowercase b). File sizes are in bytes (MB, capital B). A 100 Mb/s connection moves at most 12.5 MB/s.

2.3Binary addition and overflow

Binary addition works exactly like the column addition you learned in school, except you carry at 2 instead of 10: 0+0 = 0, 0+1 = 1, 1+1 = 10 (write 0 carry 1), 1+1+1 = 11 (write 1 carry 1).

An 8-bit register can only hold 0–255. If an unsigned sum needs a 9th bit, that bit (the carry out) is lost and the answer wraps around. This is overflow.

Worked example: Add 200 + 100 in an 8-bit unsigned register.
300 = 1 0010 1100₂ needs 9 bits. The register keeps the low 8 bits: 0010 1100₂ = 44. The carry flag is set to warn that the true answer was 300 = 256 + 44.
Real overflow bugsIn 2014 the Gangnam Style video passed 2,147,483,647 views, the largest signed 32-bit number, and YouTube had to switch its counter to 64 bits. In 1996 the Ariane 5 rocket exploded after a 64-bit value was squeezed into a 16-bit integer.

2.4Negative numbers: two's complement

Almost every computer stores negative integers in two's complement. The idea: the leftmost bit is worth a negative amount. In 8 bits, the place values are −128, 64, 32, 16, 8, 4, 2, 1.

1111 1111255−1
1111 1011251−5

The range of n-bit two's complement is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1. For 8 bits: −128 to 127.

To negate a number: invert every bit, then add 1

Why it's brilliant

The same adder circuit works for signed and unsigned numbers. Subtraction is just adding the negation: A − B = A + (inverted B) + 1. There's only one zero (sign-magnitude has +0 and −0).

Signed overflow

Overflow happens when two numbers with the same sign add to a result with the other sign: 100 + 50 in 8 bits gives 1001 0110 = −106. Adding a positive and a negative can never overflow.

Sign extension

To widen a two's complement number, copy the sign bit into the new bits: −5 = 1111 1011 (8-bit) = 1111 1111 1111 1011 (16-bit).

Other schemes

Sign-magnitude: top bit is just a minus sign (two zeros, awkward adders). One's complement: negate by inverting only (also two zeros). Both are mostly history.

2.5Bitwise operations and masks

Processors can apply logic to every bit of a word at once. These operations show up constantly in low-level code, networking and graphics.

2.6Text: ASCII and Unicode

Characters are just numbers that everyone agrees on. ASCII (1963) uses 7 bits for 128 characters: 'A' = 65 (0x41), 'a' = 97 (0x61), '0' = 48 (0x30), space = 32.

Handy ASCII patternsUpper and lower case differ by 32, which is one bit (0x20): 'A' = 0100 0001, 'a' = 0110 0001. The digit characters '0'–'9' are 48–57, so the character c has value c − 48.

Unicode gives every character in every writing system (and emoji) a number called a code point, written U+XXXX: 'é' = U+00E9, '€' = U+20AC, '😀' = U+1F600. There are over 1.1 million possible code points.

UTF-8 stores code points in 1 to 4 bytes. Plain ASCII characters keep their 1-byte codes, so old ASCII files are already valid UTF-8, which is a big reason UTF-8 now runs almost the entire web.

2.7Floating point: real numbers in 32 bits

To store numbers like 6.5, 0.001 or 3 × 10⁸, computers use scientific notation in binary: (−1)sign × 1.fraction × 2exponent. The IEEE 754 single-precision format packs this into 32 bits:

Limited precision

A float has 24 significant bits, about 7 decimal digits. A double (64 bits: 1 + 11 + 52) has about 16.

0.1 isn't exact

0.1 in binary is 0.000110011001100… forever, like 1/3 in decimal. So 0.1 + 0.2 == 0.3 is false in most languages. Never compare floats with ==; check if they're within a small tolerance.

Special values

Exponent all 0s: zero and tiny 'subnormal' numbers. Exponent all 1s: ±infinity (fraction 0) or NaN, 'not a number' (fraction ≠ 0), from things like 0/0.

Range

Largest float ≈ 3.4 × 10³⁸. Smallest normal ≈ 1.18 × 10⁻³⁸. Money should never be stored in floats; use integers counting cents.
Detailed explanationDecoding a float by hand

Take 0xC1480000 = 1100 0001 0100 1000 0000 … Sign = 1 (negative). Exponent = 1000 0010₂ = 130, so the power is 130 − 127 = 3. Fraction bits 1001 000… → significand 1.1001₂ = 1 + 1/2 + 1/16 = 1.5625. Value = −1.5625 × 2³ = −12.5.

Unit summary

Bases

Binary place values 1, 2, 4, 8, … Hex digit = 4 bits. Decimal → binary: divide by 2, read remainders upward.

Capacity

n bits → 2ⁿ values. Need ⌈log₂ N⌉ bits for N things. 1 KiB = 1024 bytes.

Signed

Two's complement: top bit worth −2ⁿ⁻¹. Negate = invert + 1. Range −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1. Overflow when same-sign inputs give an opposite-sign result.

Data

Masks with AND/OR/XOR; shifts multiply/divide by 2. ASCII 'A' = 65. UTF-8 uses 1–4 bytes. Float = sign, biased exponent, fraction; 0.1 isn't exact.
