Fetch–decode–execute, instruction sets and assembly, performance, pipelining and the memory hierarchy, with a CPU you can step through by hand.

6.1Inside a computer

Nearly every computer follows the von Neumann architecture (1945): the program and its data live together in the same memory, and a processor fetches instructions from it one at a time. That's the stored-program idea: to run different software you just load different bits into memory.

CPU

The processor. The control unit decodes instructions and sends control signals; the ALU does arithmetic and logic; registers hold the values being worked on.

Memory (RAM)

A big array of numbered bytes. Each location has an address. It holds both instructions and data.

Buses

Wires connecting the parts: the address bus says where, the data bus carries the value, the control bus says read or write.

I/O

Keyboard, screen, network, storage. Devices signal the CPU with interrupts so it doesn't have to keep checking them.
Special registerHolds
PC (program counter)the address of the next instruction
IR (instruction register)the instruction being executed
MAR (memory address register)the address being read or written
MDR (memory data register)the value going to or coming from memory
ACC / general registersdata being worked on

6.2The fetch–decode–execute cycle

A CPU does the same thing billions of times per second:

  1. Fetch: copy the PC into the MAR, read that memory location into the IR, and add 1 to the PC.
  2. Decode: the control unit splits the instruction into its opcode (what to do) and operand (what to do it to).
  3. Execute: the ALU computes, memory is read or written, or the PC is changed by a jump.

Our toy CPU has 8-bit instructions: the top 4 bits are the opcode, the bottom 4 bits are a memory address (0–15).

OpcodeBitsMeaning
HALT0000stop
LOAD a0001ACC ← memory[a]
STORE a0010memory[a] ← ACC
ADD a0011ACC ← ACC + memory[a]
SUB a0100ACC ← ACC − memory[a]
JMP a0101PC ← a
JZ a0110if ACC = 0 then PC ← a
OUT0111output ACC
Loops and ifs are just jumpsThere's no 'while' in hardware. A loop is a conditional jump backwards; an if statement is a conditional jump over the code you want to skip. Compilers turn every high-level control structure into jumps.

6.3Instruction sets and assembly

The instruction set architecture (ISA) is the contract between software and hardware: the list of instructions, registers and addressing modes a processor understands. x86-64 (Intel, AMD), ARM (phones, Apple Silicon) and RISC-V (open source) are the big ones today.

RISC (reduced)CISC (complex)
ExamplesARM, RISC-V, MIPSx86
Instructionsfew, simple, fixed length (32 bits)many, some very powerful, variable length (1–15 bytes)
Memory accessonly load and store touch memorymany instructions can use memory operands
Design goalone instruction per cycle, easy to pipelinefewer instructions per program

Assembly language is the human-readable form of machine code: one line per instruction. Here is a C statement and the RISC-V assembly a compiler might produce, with a, b, c in registers x10, x11, x12:

# C:  a = b + c - 5;
add  x10, x11, x12    # x10 = b + c
addi x10, x10, -5     # x10 = x10 - 5

# C:  if (a == 0) b = 1;
bne  x10, x0, skip    # x0 is always 0: branch if a != 0
addi x11, x0, 1       # b = 1
skip:

An assembler translates assembly into binary machine code. A compiler translates a high-level language (C, Rust) into assembly. An interpreter (Python) runs a program by executing it statement by statement inside another program.

6.4Measuring performance

How long a program takes depends on three things:

CPU time = instruction count × CPI × clock period = (IC × CPI) / f

CPI is the average number of clock cycles per instruction. A compiler lowers IC, the microarchitecture lowers CPI, and the circuit and process technology raise f. Speeding up any one of them helps.

Worked example: A program runs 2 × 10⁹ instructions with an average CPI of 1.5 on a 3 GHz CPU. How long does it take?
Time = (2 × 10⁹ × 1.5) / (3 × 10⁹) = 1.0 s.

Amdahl's law

Speeding up part of a program only helps that part. If a fraction p of the time is improved by a factor s:

Overall speedup = 1 / ((1 − p) + p / s)
Worked example: 80% of a program can run on many cores. With 8 cores, what is the speedup? With infinitely many?
8 cores: 1 / (0.2 + 0.8/8) = 1 / 0.3 ≈ 3.33×. Infinite cores: 1 / 0.2 = 5×. The 20% that stays serial caps the gain.

6.5Pipelining

A laundry analogy: wash, dry, fold. You don't wait for load 1 to be folded before washing load 2. A pipelined CPU splits each instruction into stages and works on several instructions at once, one per stage. The classic RISC pipeline has five:

StageWhat happens
IFInstruction fetch
IDInstruction decode and register read
EXExecute in the ALU
MEMMemory access (loads and stores)
WBWrite back the result to a register

Ideally a pipeline finishes one instruction per cycle (CPI ≈ 1), even though each one takes 5 cycles from start to finish. Hazards break the ideal:

Data hazard

An instruction needs a result that isn't written yet. Fixes: stall (insert bubbles) or forward the result straight from the ALU output.

Control hazard

After a branch, the CPU doesn't know which instruction comes next. Modern CPUs predict the branch direction (often >95% correctly) and throw away the work if they guessed wrong.

Structural hazard

Two instructions need the same hardware in the same cycle, such as one memory port. Fixed by duplicating hardware (separate instruction and data caches).
Worked example: A 5-stage pipeline runs 100 instructions with no stalls. How many cycles? What's the speedup over a non-pipelined CPU that takes 5 cycles per instruction?
Pipelined: 5 + (100 − 1) = 104 cycles. Non-pipelined: 500. Speedup ≈ 4.8×, approaching 5× for long programs.

6.6The memory hierarchy and caches

Fast memory is small and expensive; big memory is slow. Computers stack them:

LevelTypical sizeTypical access time
Registers~1 KB< 1 ns
L1 cache32–64 KB per core~1 ns
L2 cache0.5–2 MB~4 ns
L3 cache8–64 MB shared~10–20 ns
Main memory (DRAM)8–64 GB~60–100 ns
SSD0.5–4 TB~50–100 µs
Hard disk1–20 TB~5–10 ms

This works because programs have locality. Temporal locality: data used now will probably be used again soon (a loop counter). Spatial locality: data near what's used now will probably be used soon (the next element of an array). A cache keeps recently used data and loads it in blocks (lines) to exploit both.

An address is split into tag | index | offset. The offset picks a byte inside the block, the index picks which set to look in, and the tag is compared to check that it's the right block. In a direct-mapped cache each block has exactly one possible place, so two hot blocks with the same index keep kicking each other out (try the conflict sequence, then switch to 2-way). Bigger blocks help spatial locality (try 2- and 4-byte blocks on the array walk).

Average memory access time = hit time + miss rate × miss penalty
Worked example: L1 hits take 1 ns, the miss rate is 5%, and a miss costs 80 ns. AMAT?
1 + 0.05 × 80 = 5 ns. Cutting the miss rate to 2% gives 1 + 1.6 = 2.6 ns, nearly twice as fast.
Virtual memoryEach program sees its own private address space. The operating system and a hardware unit (the MMU) translate these virtual addresses into physical RAM addresses in 4 KB pages, using a page table. A small cache of recent translations, the TLB, keeps this fast. Pages that don't fit in RAM can be swapped to disk.

Unit summary

Architecture

Von Neumann: program and data share memory. CPU = control unit + ALU + registers. PC points at the next instruction.

Cycle

Fetch (MAR ← PC, IR ← M[MAR], PC++), decode (opcode + operand), execute. Loops and ifs are jumps.

Performance

Time = IC × CPI / f. Amdahl: 1/((1 − p) + p/s). Pipelining → CPI ≈ 1; hazards cause stalls; forwarding and prediction help.

Memory

Registers → caches → DRAM → SSD. Locality makes caches work. Address = tag | index | offset. AMAT = hit + miss rate × penalty.
